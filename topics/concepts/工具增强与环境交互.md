# 工具增强与环境交互

## 概述
Agent 通过搜索、浏览器、代码、API、数据库或物理设备改变外部状态，并依据反馈继续规划。

## 核心内容
- 工具 schema 和确定性接口决定 Agent 能观察与行动的边界。
- Agentic RAG 把检索从一次调用变成分解、导航和证据充分性检查。
- 世界模型可以模拟环境以降低真实交互成本，但会引入模拟偏差。
- 物理闭环通常仍需要人类处理材料和设备。

### 五类工具的系统分类

[[深入理解 AI Agent]] 第 4 章按调用方向和作用对象将工具分为五类：

- **感知工具**（Agent 主动调用，获取信息）：搜索、文件系统读取、API/数据库查询
- **执行工具**（Agent 主动调用，改变世界）：代码执行、文件操作、系统命令、外部 API 调用
- **协作工具**（Agent 主动调用，驱动其他 Agent 或人）：委托子 Agent、请求人类确认
- **事件触发工具**（Agent 注册、外部触发）：定时器、邮件到达、Webhook 回调——这类工具在调用方式上与前三种有本质区别，不是 Agent 主动调用而是外部驱动
- **用户沟通工具**（Agent 主动调用，向用户传递信息）：文字消息、语音通话、邮件

### MCP 协议与工具生态

MCP（Model Context Protocol）是 Anthropic 于 2024 年底发布的开放标准，采用客户端-服务器架构统一工具通信。关键设计：标准化工具描述格式（JSON Schema）、传输层灵活性（本地 stdio / 远程 Streamable HTTP）、资源与工具分离（区分"获取信息"和"执行操作"）。

### ACI 原则与工具设计演进

ACI（Agent-Computer Interface）对标 HCI（人机交互界面），核心是让工具对 Agent 而非对人友好。工具设计发展经历三代：第一代直接 API 封装（粒度过细），第二代 ACI 原则（工具对应 Agent 目标而非底层 API），第三代进一步优化工具调用、串联和发现方式——代码编排执行让 LLM 一次性生成脚本，中间变量留在执行环境，只有最终结果返回上下文，token 消耗可降低约两个数量级。

工具设计的核心原则：(1) 通用工具优于专用工具，除非存在安全/权限/性能理由；(2) 工具描述应让 LLM 知道"什么时候用"而非仅"能做什么"，清晰列出的边界条件往往比描述能力更重要；(3) 参数描述应用具体例子代替抽象规范；(4) 模型感知到的世界与工具操作的世界之间不能存在系统性偏差（禁止静默输入转换和参数注入）。
