# Coding Agent 与代码元能力

## 概述

代码生成不是 Agent 工具箱里的一个普通工具，而是一种**元能力**——能在运行时动态创造出新的工具和能力。以开放任务为目标的通用 Agent，其核心是一个 Coding Agent 加上文件系统。这个判断来自工业界实践验证：从 Manus 到 OpenClaw，成功的开放任务型通用 Agent 都遵循这一范式。

代码对 Agent 的价值体现在两个层面。**思考**上，形式化代码让思考高度严谨——自然语言描述可能有多种理解，写成代码就毫无歧义。**表达**上，一段能跑通的代码本身就是逻辑自洽的证明，执行结果提供客观的对错标准。

## 核心内容

### 七个核心工具

一个基础 Coding Agent 只需配备七个工具即可覆盖几乎所有核心动作：

1. **Code Interpreter**：隔离沙盒环境，安全执行 Python 代码
2. **Bash Shell**：执行终端命令
3. **读文件工具（Read）**：读取代码、配置、文档、日志
4. **写文件工具（Write）**：创建新文件或完全重写
5. **编辑文件工具（Edit）**：局部修改，代码维护和迭代的核心
6. **搜索文件名工具（Glob）**：模式匹配定位文件
7. **搜索文件内容工具（Grep）**：搜索文本模式

七个工具虽然简单，组合起来能完成极其多样化的任务。每类操作自然对应六个工具，第七个 Code Interpreter 对应"执行代码/计算"。

### 文件系统作为 Agent 中枢

在 OpenClaw 等通用 Agent 架构中，文件系统不仅是数据存储，更是记忆、知识和能力的中枢。Agent 长期记忆存储在 `MEMORY.md` 等 Markdown 文件中——这种设计极其有效：用户可直接阅读修改、天然保留时间顺序、可通过 Git 版本控制。

### Sessionless 设计

Agent 常驻在线，用户随时发消息即可响应。工程难点在于代码执行环境和文件系统状态如何跨消息存活：文件系统状态天然持久（工作区目录挂载在沙盒之外的持久存储上），进程状态按需保活或重建。

### 安全：致命三要素 + 持久记忆放大器

Coding Agent 同时拥有读写文件、执行命令、访问网络的权限。Simon Willison 的"致命三要素"——访问私有数据 + 暴露于不受信任内容 + 具备外部通信能力——构成完整攻击闭环。李博杰补充第四个维度：**持久记忆**作为攻击放大器，可将恶意指令跨会话潜伏。

防御体系：(1) 上下文层——来源标注、角色隔离、输入清洗；(2) 执行层——Sidecar 独立审查、Human in the loop、最小权限；(3) 沙盒隔离——默认断网 + 白名单代理放行、文件系统隔离、资源限额。

### 代码作为元能力的六个发挥方向

1. **数学与逻辑推理**：用代码求解器替代 LLM"心算"
2. **内容创作**：PPT 本质是 OOXML 代码，PDF 报告可通过代码生成
3. **知识库构建**：用代码动态组织、索引和检索知识
4. **动态创造新工具**：缺少某个工具时临时写一个
5. **Agent 自举**：Agent 通过生成代码改进自身
6. **数据格式桥接**：数据格式变了，动态生成解析逻辑

## 证据与来源

[[深入理解 AI Agent]] 第 5 章系统阐述了 Coding Agent 架构，以 OpenClaw 为主线展示了通用 Agent 的 Coding 内核。Manus、Claude Code、OpenClaw 等多个产品验证了这一范式。

## 分歧与不确定性

- "Coding Agent 是通用 Agent 核心"的适用边界：垂直领域 Agent（客服、语音助手）的任务空间相对封闭，代码在其中更多是工具箱里的一件工具而非架构中枢
- 代码生成的安全问题——沙盒隔离、命令语义解析——目前以工程手段为主，尚未形成理论框架
