## 核心摘要

全书围绕核心公式 **Agent = LLM + 上下文 + 工具**（大脑 + 眼睛 + 手脚）展开，共十章，沿"构建—评估与进化—交互与协作"三个层次推进。全书正文、配图和 92 个配套实验全部开源。作者在 Pine AI 打造了第一个能自主与真人交互、可靠处理涉及金钱的长程通用 Agent，书中的架构原则来自这些高风险实战经验。

## 关键论点

### 1. 核心公式：Agent = LLM + 上下文 + 工具

三者缺一不可，分别对应 RL 中的策略（Policy）、观察空间（Observation Space）和动作空间（Action Space）。直觉层理解为大脑 + 眼睛 + 手脚。

### 2. 实践在前，命名在后

Skill、Harness、Loop Engineering 等概念并非大公司先发明——大量 Agent 产品早就在这么做，Anthropic 等公司后来才提炼命名。这意味着"等名词流行再实践"就已经慢了一步。保持对 Agent 能力上限有极高要求的真实业务，建立评估机制，才能赶在名词流行之前就知道该怎么做。

### 3. 上下文工程决定 Agent 能力上限

模型智力只是基础，上下文质量才是真正上限。一个中等模型配上精心组织的上下文，往往能胜过顶级模型在信息匮乏下的盲目摸索。上下文工程不仅是技术问题，更根本的是组织问题——团队本身必须是信息透明的。

### 4. Coding Agent + 文件系统是通用 Agent 的核心

代码生成不是众多工具之一，而是一种元能力。七个核心工具（Code Interpreter、Bash、Read、Write、Edit、Glob、Grep）构成通用 Agent 的基础。文件系统是 Agent 记忆、知识和能力的中枢。

### 5. SFT 记忆，RL 泛化

模型后训练的核心洞察：SFT 倾向于记住训练数据里的答案，RL 学会可迁移的策略。"数据与环境比算法更重要"是工业界最反直觉也最值钱的经验。

### 6. Agent 必须从运行经验中持续进化

部署后的 Agent 需要"评价→对照→归纳→验证"的持续进化闭环。四种更新载体：经验知识库、Prompt 与 Skill、程序与 Harness、模型参数。模型尚未能可靠持续学习时，必须把"学习"构造成模型外围的自主系统。

### 7. Harness 不会消失，只会向新前沿迁移

模型会一层层吃掉 Harness，但这个"吃"永远不会完结——训练以月计、模型无法内化所有局部约束、每一代模型打开新的能力前沿。Harness 工程不是对《苦涩的教训》的抵抗，而是这一教训在工程时间尺度上的实践。

### 8. 多 Agent 的真正价值在"新信息"

多 Agent 何时真正优于单 Agent 的核心判据：协作过程是否引入了单个 Agent 生成时无法获得的新信息（如代码执行反馈、视觉渲染截图、外部工具验证）。

## 待验证问题

- 书中大量案例来自 Pine AI 和头部 Agent 产品的闭源实践，部分架构决策无法独立验证
- "实践在前命名在后"的叙事主要基于作者自身经验，其他厂商的独立时间线有待交叉验证
- 模型后训练章节（第7章）的实验结论依赖特定基础模型版本，随模型演进部分定量结论可能变化
