# Agent 管理原始材料设计

日期：2026-07-25  
状态：待用户书面审阅

## 目标

让获得 Vault 写入权限的 Agent 在用户授权的知识任务中，将可追溯的原始材料新增到 `Clippings/`，使知识页不再只依赖外部链接。同时继续保护用户通过 Obsidian Web Clipper 或其他方式收藏的既有内容。

本次先为 2026 年 AI Agent 研究材料落地，目录为：

```text
Clippings/
└── AI Agent/
    └── 2026/
        ├── PDF/
        └── Web/
```

## 方案选择

采用“原始工件 + Wiki 来源页”的双层存储：

- 可公开下载的论文或技术报告保存为 PDF，Obsidian 可直接预览。
- 只有官方网页、没有独立 PDF 的材料保存为 Markdown 网页快照。
- `topics/sources/` 中的来源页继续承担中文摘要、论点提炼、关联概念与不确定性说明，并增加本地原始材料链接。
- `system/source-state.json` 记录每个原始工件的路径、大小、修改时间、SHA-256、处理状态和对应来源页。

不把 HTML、PDF 与全文摘要全部塞进同一个 Markdown 文件，以免搜索结果重复、知识页职责混乱。

## Clippings 写入权限

默认规则从“Agent 绝对只读”调整为“受控新增、既有内容只读”：

1. 用户明确要求搜集、下载、剪藏或保存来源时，Agent 可以在该任务范围内向 `Clippings/` 新增文件和目录。
2. Agent 不得覆盖同名文件；发生冲突时比较 SHA-256。内容相同则复用，内容不同则停止该文件写入并报告冲突。
3. Agent 不得自动修改、重命名、移动或删除任何既有 `Clippings/` 文件，包括 Agent 过去新增的文件。
4. 修改、替换、重命名、移动或删除仍须用户逐项或明确批量授权。
5. 下载采用临时文件，验证成功后再原子移动到目标路径；失败文件不进入正式目录。
6. `Clippings/` 的写入本身不使用 Wiki 写锁；由其触发的 `topics/`、`system/` 增量摄取必须取得写锁。

这样可以兼容用户手工使用 Obsidian Web Clipper：用户剪藏与 Agent 新增材料进入同一增量检测流程，但 Agent 不会碰已有剪藏。

## 文件与元数据

### PDF

文件名使用稳定、可读的英文论文标题，清除 Windows 禁用字符；不加入随机编号。来源页至少记录：

- 论文标题、机构、发布日期；
- 原始 URL 与直接 PDF URL；
- 本地 `[[Clippings/.../PDF/文件名.pdf]]` 链接；
- 抓取日期；
- SHA-256；
- 出版状态或同行评审状态。

### 网页快照

文件名使用官方页面标题，格式为 UTF-8 Markdown。Frontmatter 至少包含：

```yaml
---
type: clipping
source_kind: official-web
title: 页面标题
organization: 机构
published: YYYY-MM-DD
captured: YYYY-MM-DD
source_url: https://...
---
```

正文保留页面标题、作者/机构、发布日期、正文文本、图表说明以及原始链接。动态组件、评论区、导航和广告不纳入。若页面禁止获取或正文无法可靠抽取，则只保存带失败说明的来源元数据，不伪装成完整快照。

## 数据流

1. 从已审计的 16 项来源读取官方落地页与论文入口。
2. 优先获取出版方或 arXiv 的 PDF；没有 PDF 时获取官方网页并转换为 Markdown 快照。
3. 校验 HTTP 状态、文件类型、非空内容和 SHA-256，然后新增到 `Clippings/AI Agent/2026/`。
4. 扫描新增材料并更新 `system/source-state.json`。
5. 将 16 个 `topics/sources/` 页面链接到相应本地材料；同一研究的论文 PDF 与官方说明页可以同时作为来源。
6. 更新综述、学习地图、索引、摄取日志和 Lint 报告中受影响的引用。
7. 验证所有本地链接、Frontmatter、JSON、PDF 可读性、工作树范围与写锁释放情况。

## 失败与边界

- 付费墙、登录墙、robots 限制或下载失败：保留外部链接，在审计与日志中标为未落地，不绕过访问控制。
- 官方博客与论文内容不一致：分别保存并在来源页标注差异，不静默合并。
- 网页发生更新：将其识别为潜在新版本，不自动覆盖旧快照。
- 体积异常或内容类型伪装：拒绝入库并报告。
- DeepSeek 当前没有符合严格 2026 Agent 研究口径的条目，因此不制造空 PDF 或用一般模型报告替代。

## 验收标准

- `VAULT_SCHEMA.md` 与 `AGENTS.md` 明确允许“用户授权下的受控新增”，同时保留既有材料保护条款。
- 对 16 个已纳入研究条目逐项尝试落地；所有可公开、合法获取的条目都具有至少一个库内原始材料，客观无法获取的条目在来源页和审计中明确记录失败原因。
- 所有 PDF 能被 PDF 解析器打开；所有网页快照具有合法 Frontmatter、正文和原 URL。
- 每个本地工件都有 SHA-256，并被 `system/source-state.json` 跟踪。
- 16 个来源页均能导航到对应本地工件。
- `Clippings/llm-wiki.md` 和用户现有文件不被修改。
- Lint 无非预期断链；本任务不改动 `CLAUDE.md` 等用户既有修改，任务结束时无写锁残留。
