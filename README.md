# Local_Knowledge_Base

一个以 Obsidian 为主要浏览与编辑界面、由 AI Agent 协助维护的本地知识库。

本项目的核心目标不是构建某个单一主题的资料集合，而是探索一套可持续积累、相互链接、保留原始证据并可由 Git 追踪演进过程的本地知识管理方法。当前的 **AI Agent 知识板块**是这套方法的第一个实践验证案例，不代表项目只能用于 AI Agent 研究。

## 项目目标

- **本地优先**：知识文件和原始资料保存在本地 Obsidian Vault 中，是否同步到远程由用户决定。
- **来源可追溯**：重要事实、结论和综合判断能够回到原始论文、网页快照或其他材料。
- **知识可演进**：新材料进入后更新已有主题，而不是不断生成彼此孤立的笔记。
- **人机协作**：用户决定研究方向和重要操作，AI Agent 负责资料提炼、知识关联、索引维护与一致性检查。
- **过程可审计**：使用状态清单、操作日志、内容哈希和 Git 历史记录知识库的变化。

## 目录结构

```text
Local_Knowledge_Base/
├── Clippings/          # 原始资料：论文、网页快照和附件
├── topics/             # 经过提炼和组织的长期知识
│   ├── index.md        # 知识库总入口
│   ├── sources/        # 单份原始资料的来源页
│   ├── concepts/       # 概念、方法和原则
│   ├── entities/       # 人物、机构、项目和工具
│   └── syntheses/      # 跨来源综述、比较和学习地图
├── system/             # 导入状态、维护日志、Lint 和研究清单
├── VAULT_SCHEMA.md     # 所有 AI Agent 共用的知识库协议
├── AGENTS.md           # Codex 的入口规则
└── CLAUDE.md           # Claude Code 的独立入口文件
```

各目录的职责：

- `Clippings/` 是事实追溯的源头。已有资料默认只读；只有在用户明确授权时，Agent 才能受控新增材料。
- `topics/` 是知识库主体，保存从原始资料中提炼出的来源页、概念、实体关系和综合分析。
- `system/` 是维护层，记录增量导入状态、内容哈希、操作日志、健康检查结果和阶段性研究清单。
- `tmp/` 如存在，仅用于下载或渲染过程中的临时文件，不属于长期知识资产。

## 知识流转

```text
原始资料
Clippings/
    ↓ 阅读、校验与忠实提炼
单份资料卡
topics/sources/
    ↓ 关联与归纳
概念和实体
topics/concepts/ + topics/entities/
    ↓ 跨来源综合
学习地图与研究综述
topics/syntheses/
```

知识页通过 Obsidian Wiki 链接互相连接。来源页负责保留证据边界，概念页负责聚合稳定知识，综合页负责明确区分来源事实、已有结论和新的综合判断。

## 快速开始

1. 使用 Obsidian 打开本项目根目录作为 Vault。
2. 从 [`topics/index.md`](topics/index.md) 进入知识库。
3. 通过概念页或综合页浏览主题，再沿 Wiki 链接进入来源页。
4. 需要核对证据时，从来源页打开 `Clippings/` 中对应的原始 PDF 或网页快照。

如果需要加入新资料，可以手动保存到 `Clippings/`，也可以明确授权 AI Agent 搜集和保存。新材料随后应经过增量导入，更新相关来源页、主题页、索引和维护状态。

## AI Agent 如何参与

所有参与维护的 AI Agent 都应遵循 [`VAULT_SCHEMA.md`](VAULT_SCHEMA.md)，主要职责包括：

- 扫描新增、变化、失败或缺失的原始资料；
- 为单份资料建立忠实、可追溯的来源页；
- 提取值得长期维护的概念、实体、关系和知识缺口；
- 更新已有主题与综合页面，避免机械制造重复笔记；
- 检查 Wiki 链接、Frontmatter、索引覆盖和来源一致性；
- 在写入共享知识层时使用写锁，避免多个 Agent 同时修改。

不同 Agent 可以拥有独立的入口规则，但不能把私有会话、缓存或模型设置当作知识来源。用户的明确指令始终具有最高优先级。

这个板块用于验证以下能力：

- 原始材料能否完整保留并在 Obsidian 中直接访问；
- 单篇论文能否形成可复用、可追溯的知识页；
- 多来源信息能否逐步聚合为概念、实体关系和研究综述；
- AI Agent 能否在不破坏用户材料的前提下安全维护知识库。

未来可以沿用同一套结构扩展到编程、数学、金融、历史、科研或个人学习等其他领域。

## 版本管理与数据边界

Markdown 知识页、维护状态和原始材料可以通过 Git 保留历史，但远程同步并不是知识库运行的必要条件。提交或推送前，应检查文件体积、版权、隐私和敏感信息，并由用户决定哪些内容适合进入远程仓库。

项目不会把聊天记录本身视为长期知识。只有保存为本地来源并经过提炼、链接和验证的内容，才进入可持续维护的知识层。
